## 2. 关键设计取舍

1. **core 层不依赖 Android 资源**
   `ItemType` / `ItemSupport` / `Sensitivity` / `CapabilityMatrix` 都是纯 JVM 类型，文案在 `ui/common/Labels.kt` 用 `when` 映射。
   代价是多一个映射文件，收益是协议与能力逻辑可以脱离设备跑单元测试。

2. **未知字段必须跳过**
   `TlvReader` 对未知 tag 只做长度前移、不抛异常，符合协议 §7.1「未知 tag 必须跳过」的前向兼容要求；
   只有缺失关键字段才返回 `0x1002 MISSING_FIELD`。

3. **策略开关与密钥严格分离**
   `TransferSettingsStore`（SharedPreferences）只保存冲突策略、EXIF 位置开关等**非敏感策略**；
   会话密钥仅存内存，协议 §10 明确禁止落盘。

4. **启动期零权限、零阻塞**
   `PhoneTransferApp` 只做懒加载；`MainActivity` 直接显示主界面。
   这不只是体验取舍，也是「不得先跑再要权」的合规要求。

5. **能力以实测为准**
   `CapabilityMatrix` 是设计基线，注释与界面都写明：最终能力由 CAPABILITY_QUERY/RESPONSE 的实测结果决定，
   界面只负责渲染数据源，替换数据源不需要改 UI。

## 3. 继续开发的建议顺序

1. **通道层**：新建 `core/transport/`，实现 Wi-Fi Direct / Soft AP / LAN 三选一的自动降级链（PoC P1 的决策表）。
2. **会话管理器**：串联 `SessionStateMachine` + `FrameCodec` + `CryptoEngine`，
   按 §9~§13 实现握手、协商、传输、校验四个阶段；收到 `SESSION_CLOSE` 立即销毁密钥。
3. **数据适配器**：`core/data/` 下按 `ItemType` 注册适配器，先做联系人、照片、视频、日历（可行性最高、跨平台稳定）。
4. **功能区 UI**：在 `TransferFragment` 中按注释里的五步顺序接入；权限申请一律发生在 `ITEM_SELECT` 之后。
5. **迁移报告**：`SESSION_CLOSE` 携带的 JSON 报告落为本地文件，并填充「我的 → 迁移报告」页。
